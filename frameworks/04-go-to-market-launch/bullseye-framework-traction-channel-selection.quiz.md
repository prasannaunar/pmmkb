# Quiz: Bullseye Framework (Traction Channel Selection)

1. A team has a small test budget and splits it across seven different channels to "cover all the bases" before committing to any one. What does the framework predict?
   - **A.** Cap the middle ring at three or four channels, with a minimum spend per test.
   - **B.** Cap the ring at four channels, but keep splitting the same total budget across all seven.
   - **C.** Testing more channels simultaneously always produces a clearer, faster read.
   - **D.** Test all 19 channels at once with an equal budget split across each.

   **Correct answer: A.** Testing too many channels at once with too little budget per test is a named pitfall: splitting a small budget across six or seven channels means no single test produces a meaningful read, and the team ends up choosing on gut feel anyway. The fix is capping the middle ring at three or four channels and setting a minimum spend per test.

   *Why not B:* Naming a smaller ring does not help if the same thin budget still gets spread across all seven channels; the fix requires actually cutting spend to the promoted three or four, not just relabelling the ring.

   *Why not C:* More simultaneous channels with the same total budget dilutes each test below a meaningful threshold; the framework explicitly ties clarity to fewer, better-funded tests, not more, thinner ones.

   *Why not D:* All 19 channels are brainstormed and triaged in the outer ring, but only three or four are promoted to the funded middle-ring test; testing all 19 with equal budget contradicts the framework's explicit sequencing.

2. A board member suggests a specific channel because a competitor uses it, and the team commits a full-scale budget to it immediately, skipping any cheap test. What pitfall does this describe?
   - **A.** Require every channel to pass a time-boxed, capped-budget test before full investment.
   - **B.** Run a shorter, informal two-week test before committing the full-scale budget.
   - **C.** A board member's suggestion is sufficient validation to skip testing.
   - **D.** The issue is only that the channel was suggested by a board member.

   **Correct answer: A.** Confusing an outer-ring brainstorm entry with a validated channel is a named pitfall: teams sometimes commit real budget to a channel because a competitor uses it or a board member suggested it, skipping the middle-ring test entirely. The fix is requiring every channel to pass a time-boxed, capped-budget test before any full-scale investment, no exceptions for channels that "obviously" should work.

   *Why not B:* An informal test without the agreed success metric and cost cap the framework specifies doesn't produce the comparable evidence a real middle-ring test does; it looks like validation without actually being the structured test the framework requires.

   *Why not C:* A board member's suggestion is not a substitute for the framework's required cheap test; the methodology explicitly treats this kind of "obvious" suggestion as exactly the case requiring no exception.

   *Why not D:* The source of the suggestion (board member versus another stakeholder) is not the core issue; the problem is skipping the validation test regardless of who proposed the channel.

3. A team runs middle-ring tests and finds two channels performing almost identically well on the agreed metric. They decide to fund both at half-strength rather than choosing one. What does the framework say about this decision?
   - **A.** Run one more comparative test round rather than funding both indefinitely.
   - **B.** Pick whichever channel scored marginally higher, even if the gap isn't meaningful.
   - **C.** Abandon both channels and restart the outer-ring brainstorm from scratch.
   - **D.** Break the tie by whichever channel has the lower absolute cost.

   **Correct answer: A.** Running two or three channels in the inner ring simultaneously because each shows some traction is a named pitfall: diluting focus across multiple modestly performing channels usually grows slower than concentrating the same budget on the single best performer, since economies of scale only show up with enough volume and iteration. The fix is running one more comparative test round rather than funding both indefinitely at half-strength.

   *Why not B:* Two channels performing "almost identically" is exactly the case where a small, marginal difference isn't real evidence of a winner; the fix is a further test round that can actually separate signal from noise.

   *Why not C:* Restarting the entire brainstorm is unnecessary; the two channels already passed the middle-ring test successfully, and the fix is simply another comparative round between just those two, not discarding all prior work.

   *Why not D:* The framework does not name absolute cost as the tiebreaker; it calls for another test round using the originally agreed success metric, not switching to a different, unstated criterion.

4. A company's single dominant channel has been driving most of its growth for over a year, but growth from that channel has recently begun to visibly slow as the addressable audience within it saturates. What does the framework recommend?
   - **A.** Return to the outer-ring brainstorm and test the next candidate channel.
   - **B.** Increase spend on the same channel for one more quarter before looking elsewhere.
   - **C.** Switch to a completely different business model, since fit itself has failed.
   - **D.** Leave the plateau unaddressed and wait at least two more years before acting.

   **Correct answer: A.** The framework explicitly calls for treating a plateau in the dominant channel as the trigger to re-run the outer-ring brainstorm and test the next candidate, since growth from any single channel eventually slows as its addressable audience saturates.

   *Why not B:* Delaying the re-brainstorm by another quarter of extra spend is exactly the wrong order: the framework treats a visible plateau as the signal to act now, not to first test whether more budget can push past a genuine saturation ceiling.

   *Why not C:* A single channel plateauing does not indicate a product-market fit failure; the framework assumes product-market fit is already validated and treats channel saturation as a distribution question, not a fit question.

   *Why not D:* The framework calls for acting on the plateau as soon as it's observed, not waiting an arbitrary further period; delaying the re-brainstorm only prolongs stagnant growth.

5. A team is deciding how to test five channels shortlisted from the outer-ring brainstorm and wants each test to run for six months before comparing results, to be thorough. What does the framework suggest about this test design?
   - **A.** Run the tests in parallel with a fixed two-to-four-week window.
   - **B.** Run the tests in parallel, but let each one run for six months to be thorough.
   - **C.** Run the tests sequentially, one fully tested before the next begins.
   - **D.** The number of channels tested does not matter as long as the window is long.

   **Correct answer: A.** The framework calls for a fixed, time-boxed test window, typically two to four weeks, run in parallel across the promoted middle-ring channels, to get a comparative read faster and avoid one channel's test window drifting into the next quarter's planning cycle.

   *Why not B:* Running the tests in parallel gets the structure right, but a six-month window is far past the two-to-four-week window the framework names; the extended timeline delays the comparative read the middle ring is meant to produce quickly.

   *Why not C:* The framework explicitly recommends running middle-ring tests in parallel, not sequentially, specifically to get a faster comparative read across channels.

   *Why not D:* The framework also caps the middle ring at three or four channels; five channels already exceeds the recommended range, regardless of how the test window is set.
