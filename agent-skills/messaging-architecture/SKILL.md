# Messaging architecture

The messaging house is the single source of truth every asset writes from: one
core message, three or four value pillars, and proof beneath each. It encodes
positioning; it does not decide it.

Paths below are relative to the knowledge base root. Full entries are in
`frameworks/02-positioning-messaging.md`.

## Entry condition

Start only from validated positioning that already names the target segment,
the category, and the core differentiator. If positioning is unsettled, stop
and use `positioning-development`; building a house on an unsettled foundation
encodes the confusion and makes it harder to unpick later.

## Procedure

1. **Restate the positioning inputs** in one paragraph: segment, category,
   competitive alternatives, unique attributes, and the value each carries.
   Everything below has to trace back to this paragraph.
2. **Write the core message (the roof).** One sentence, in the buyer's
   language, led by the outcome rather than the mechanism. Draft three or four
   candidates and choose by clarity, not cleverness. It must be repeatable from
   memory and true only of you.
3. **Define three or four value pillars (the walls).** Each maps to a priority
   the target buyer already has and answers "why believe the core message?".
   Name them as benefits, not feature categories. Keep them distinct enough
   that a claim clearly belongs under one pillar and not two.
4. **Populate proof points (the foundation).** Two to four per pillar: a
   specific capability, a quantified result, a named customer outcome, or
   third-party validation. A pillar with no proof is a slogan; cut it or find
   the evidence.
5. **Ladder raw features into proof.** For any feature that reads as a spec,
   run the FAB ladder: feature, then the advantage it creates, then the benefit
   the buyer would repeat back. Only the benefit level belongs in copy; the
   feature belongs in the proof column beneath it.
6. **Build the message matrix.** Personas or journey stages down the side, the
   adapted core message and pillar emphasis across the top. Note which pillar
   leads for each persona and how the wording shifts. Use
   `assets/message-matrix.md`.
7. **Adapt by segment through the buying trigger, not by rewriting.** For a
   vertical or segment variant, identify that segment's specific triggering
   event and route it to the one existing pillar that answers it. Producing a
   fourth pillar for every new vertical is how a house becomes unusable.
8. **Test before it scales.** Run the draft past a verified target-buyer panel
   (not colleagues) for clarity, relevance, and differentiation. If they cannot
   restate the core message, simplify. Remove any claim a competitor could make
   word for word.
9. **Publish and govern.** Store as the single source of truth, brief every
   writer against it, version it, name one owner (PMM), and review each quarter
   or whenever positioning changes.

## Quality gate

- [ ] Core message is one sentence, outcome-led, and restatable from memory
- [ ] Three or four pillars, each mapped to a stated buyer priority
- [ ] Every pillar carries at least two proof points, each with a source
- [ ] No claim survives that the strongest competitor could make verbatim
- [ ] Tested with target buyers, not internal stakeholders
- [ ] Named owner and review date recorded

## Gotchas

- **Pillars named after feature categories fail immediately.** "Reporting" is a
  feature category; "prove posture to auditors in minutes" is a pillar. If a
  pillar name would appear in a product spec, rewrite it as the outcome.
- **Five or more pillars means the positioning is not settled.** The overflow
  is usually an unresolved argument about who the product is for. Go back to
  `positioning-development` rather than adding a wall.
- **Internal review is not message testing.** Colleagues know what the product
  does and will fill gaps automatically. Message testing needs buyers who have
  never seen it, which is the entire point of the discipline.
- **Proof degrades.** A named customer outcome from two years ago, or a
  benchmark from a since-deprecated product version, reads as a fabrication
  when a prospect checks it. Refresh proof each quarter alongside the review.
- **A vertical variant is a routing exercise, not a rebuild.** Each segment's
  buying trigger points at one existing pillar. Rebuilding the house per
  vertical produces four incompatible pitches, which is the problem the house
  existed to solve.
- **Narrative and hierarchy are different altitudes.** If the need is a single
  asset that has to land as a story (homepage, video script, founder keynote),
  use the StoryBrand SB7 or Strategic Narrative entries in the same category
  and feed them the house's pillars, rather than trying to make the house
  itself narrative.

## Output

Deliver the completed house (`assets/messaging-house.md`), the message matrix
(`assets/message-matrix.md`), the test results with the panel composition, and
the governance line: owner, version, next review date.
